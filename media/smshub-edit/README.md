# SMS Hub — промо-эдит

Рекламный ролик про SMS Hub (Telegram Mini App: номера → SMS → Telegram), смонтированный
под трек из референса (`8463801104_1_tiktok_*.mp4`, OSINT-эдит). Стиль оттуда же: чёрный фон,
отражения под логотипами, медленные непрерывные наезды. Все переходы — мягкие наплывы с
расфокусом, без резов, тряски и глитчей.

Ключевое отличие от эдита X-Style: интерфейс здесь **снят в движении**, а не панорамами по
скриншотам. Каждый кадр приложения отрисован отдельно, поэтому в ролике реально идёт загрузка
с прогресс-баром, прокрутка, поднимается шторка заказа, прилетает новая SMS и всплывает тост
о скопированном коде.

## Как пересобрать

Сборка идёт в два прохода: сначала снимается движение интерфейса, потом поверх него монтируется
сам ролик.

### Проход 1 — движение приложения

Нужен репозиторий `sms-tg-forwarder`, поднятый статикой:

```bash
cd /путь/к/sms-tg-forwarder
python3 -m http.server 8900 &
```

```bash
cd media/smshub-edit/src
npm install                 # playwright-core
node app-shoot.js           # 405 кадров интерфейса в src/app/ (~2.5 мин)
```

`app-shoot.js` подменяет `/api/bootstrap` данными из `sms-demo.js`, заглушает
`telegram-web-app.js`, замораживает таймеры страницы и **сам анимирует интерфейс покадрово**:
прогресс загрузки, прокрутку, поднятие шторки, прилёт новой SMS, нажатие на код и тост.
Из-за этого движение получается ровно 60 fps и повторяемым от прогона к прогону.
Переменные окружения: `APP_URL` (по умолчанию `http://127.0.0.1:8900`), `CHROME_PATH`.

### Проход 2 — монтаж

```bash
node shoot.js preview 6.5 9.4   # отдельные кадры в preview/
node shoot.js all               # 720 кадров ролика в frames/ (~8 мин)
node shoot.js range 246 670     # перерисовать только часть кадров
```

Сборка (`REF` — исходное видео, из него берётся звук):

```bash
REF=/путь/к/референсу.mp4
FX="eq=contrast=1.03:saturation=1.04,format=gbrp,split[a][b];\
[b]lutrgb=r='if(gt(val,190),val,0)':g='if(gt(val,190),val,0)':b='if(gt(val,190),val,0)',\
gblur=sigma=22,format=gbrp[bl];\
[a][bl]blend=all_mode=screen:all_opacity=0.22,format=yuv420p,noise=alls=3:allf=t+u[v]"

ffmpeg -framerate 60 -i frames/f_%05d.png -i "$REF" \
  -filter_complex "$FX;[1:a]afade=t=out:st=11.05:d=0.35,apad=whole_dur=12.0[aud]" \
  -map "[v]" -map "[aud]" -c:v libx264 -crf 19 -preset slow -pix_fmt yuv420p -r 60 \
  -c:a aac -b:a 192k -ac 2 -movflags +faststart ../SMSHUB_edit_1080x1920.mp4 -y
```

## Что где править

`src/app-shoot.js` — сценарий движения интерфейса: функция `window.__drive(t)` описывает, что
происходит на экране в момент `t` (секунды от старта приложения). Хочешь показать другой экран
или другой порядок — правится там.

`src/edit.html`:

- **Сцены и наплывы** — массив `CUES` (`t0`/`t1`, `fi`/`fo` — длительность появления и ухода).
- **Движение камеры по телефону** — массив `CAM`: `[время, масштаб, сдвиг Y, сдвиг X]`.
  Между станциями идёт плавная интерполяция, поэтому камера не останавливается ни на кадр.
- **Скорость показа интерфейса** — массив `MAP`: пары «время ролика → время записи приложения».
- **Подписи** — массивы `LAB` (нижняя подпись) и `TOP` (чип сверху).
- **Цвета** — переменные в `:root`.

Демо-данные (номера, отправители, коды) — `src/sms-demo.js`. Перед публикацией их стоит
заменить на реальные.

Шрифты: Montserrat, Inter (Google Fonts, SIL Open Font License), лежат в `src/fonts/`.
